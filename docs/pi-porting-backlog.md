# Pi features to port to Panda

We compared Panda 0.1.12 (`143851c`) with Pi main (`5a14e69`) on 18 November 2026. The priorities cover the Rust coding harness and its terminal and programmatic hosts. The comparison mentions Pi's optional tools and other products where they affect a porting decision. [Panda snapshot][panda] · [Pi snapshot][pi] · [Panda's first-release goals](initial-plan/PLAN.md)

Start with three changes users can exercise independently: let scripts select a model and run without saving a session, add regex or glob search within a subtree in plan mode, and let users export and reimport a branched session. Decide in parallel whether Panda must run existing Pi TypeScript extensions unchanged. That decision determines the extension loader, package compatibility, and how much of Pi's Node and terminal API has to be reproduced.

Panda already streams text, reasoning and shell output, handles tool calls and cancellation, queues steering and follow-ups, and supports file and clipboard-image input. It has a Vim editor, skill search and loading, session search and resume, branch navigation and summaries, fork and clone, reply copying, transient retries, and manual and automatic compaction. Preserve its Seatbelt policy, dispatch-enforced plan mode, and explicit recovery of interrupted calls when adding the behaviors below. [Current CLI](../README.md) · [Existing parity regressions](pi-feature-map.md) · [Turn tests](../crates/core/tests/turn.rs)

## First ports for the coding CLI

| Feature | Panda 0.1.12 | Rust work and acceptance checks |
|---|---|---|
| **1. Reproducible CLI invocations** | Print, JSON, RPC and `--continue`. A positional prompt selects print mode. Print reads stdin only when the argument prompt is empty. Model and reasoning choices live in interactive commands. | Add per-run provider/model/thinking and tool selection, `--no-session`, explicit session ID/directory, and system-prompt controls. Cover Pi's interactive initial prompt and piped-input behavior. Check that piping a diff plus a review instruction sends both in one request, selects the requested model, and leaves no saved conversation. [Pi CLI][cli] · [Panda argument parser and print path](../crates/cli/src/automation.rs) |
| **2. Read-only exploration** | `search` does paginated literal matching. `repo_map` walks files and skips a fixed set of directories. | Add Pi's optional `grep`, `find` and `ls` capabilities: regex or literal matching, case control, path/glob filters, surrounding lines, ignore-file rules for search/find, and immediate directory entries. Check a nested ignored file, a context match and an empty directory in plan mode. [Pi tools][tools] · [Panda traversal](../crates/local/src/files.rs) |
| **3. Multi-edit, image reads and recoverable command output** | `edit` replaces one unique string and reports a diff. `read` returns UTF-8 text or a line range. User-attached images work. Shell has a fixed 120-second worker deadline and caps captured output. | Batch disjoint edits against the original file, reject the whole batch on overlap or ambiguity, and return a structured patch. Allow model-initiated image reads and typed image results. Expose a bounded per-command timeout and a retrievable full-output file when a transcript excerpt is truncated. Check that an invalid second edit leaves the first unapplied and that a long test log remains readable through the sandbox. [Pi tool implementations][tools] · [Panda schemas](../crates/coding/src/lib.rs) · [Worker limits](../crates/local/src/sandbox.rs) |
| **4. Portable sessions** | SQLite stores the active history and its tree. RPC can return the loaded session. There is no Pi JSONL importer, portable tree export, or HTML transcript command. | Implement local JSONL import/export and standalone HTML export. Map external session and entry IDs, parent links, working directory, model changes, labels and summaries. Specify how unknown extension entries round-trip. Import and export a Pi fixture with two branches, a tool result and a compaction, then reopen the export. [Pi session format][format] · [Pi import/export commands][commands] · [Panda tree storage](../crates/local/src/store/tree.rs) |
| **5. Resume, fork and tree behavior** | `--continue` selects the highest session ID for the workspace. The picker can search transcript content. `:fork N` copies through completed answer N. Tree navigation can restore a user prompt into the editor. | Continue the most recently modified session. Add cross-workspace selection with explicit working-directory handling, fork from a chosen **user prompt** into a new session, entry labels/bookmarks and tree filters, and picker rename/delete/sort actions. Check that editing an older session makes it the next continuation and that a forked prompt can be revised before it is sent. [Pi session lookup][sessionsrc] · [Pi session workflows][sessions] · [Pi tree keys][keys] · [Panda lookup and fork](../crates/local/src/store.rs) |
| **6. Compaction and output-limit recovery** | Panda checkpoints before model calls, including after tools, and retries a context overflow after compaction. Manual compact summarizes through the end. The chat-completions decoder treats a `length` stop as an error. Both summary prompts are fixed. | Accept instructions on manual compact and branch summary. Retain a configurable recent suffix, track read/modified files across summaries, and handle an early output-token limit distinctly from input overflow. Preserve incomplete attempts in raw history and keep incomplete tool calls from executing. Check the next provider request after manual compact and after a length-limited response. [Pi compaction and recovery][compact] · [Panda checkpoints](../crates/core/src/lib.rs) · [Panda stop reasons](../crates/providers/src/lib.rs) |

## Foundations for extensions and integrations

| Feature | Panda 0.1.12 | Remaining Rust work |
|---|---|---|
| **7. Settings, resource discovery and project trust** | Environment variables, a saved model choice, workspace/user skill roots, and layered `AGENTS.md` instructions. The coding system prompt is assembled in Rust. | Resolve user settings, project overrides and invocation flags consistently. Add a settings UI, resource diagnostics and reload, `AGENTS.override.md` / `CLAUDE.md` precedence, and system-prompt replacement/append files. Make trust in project-provided extensions and MCP server definitions explicit before loading them. Test trusted and declined startup against the same repo. [Pi configuration][config] · [Pi trust rules][trust] · [Panda startup](../crates/cli/src/main.rs) |
| **8. Prompt templates and skill metadata** | Named Markdown skills and on-demand search/load already work. The skill parser reads name and description, and discovery checks files named `SKILL.md`. | Discover Markdown prompts as commands with quoted arguments, positional substitutions, defaults and slices. Add skill validation, ancestor project discovery, invocation restrictions and collision diagnostics. Alongside Panda's on-demand search, give the model an optional startup index of skill descriptions like Pi's. [Pi templates][templates] · [Pi skills][skills] · [Panda library](../crates/local/src/skills.rs) |
| **9. Extension API and loader** | A compiled host can implement `Provider`, `Store`, `Toolset`, `Workspace` and `Skills`. The shipped CLI uses a fixed tool catalog and command dispatcher. | Load extensions at runtime. Start with register/unregister tool and command, session/turn/tool hooks, tool veto and result transformation, custom persisted entries, and clean reload/shutdown. Then add shortcuts, flags, providers, dialogs, widgets and renderers. First acceptance case: load a tool and a command, run them, reopen the session, and reload once without duplicate registration. **Compatibility decision:** a Rust-native plugin contract serves new extensions. Running unmodified Pi packages also requires their TypeScript/Node imports and relevant Pi APIs. [Pi extension API][ext] · [Panda host traits](../crates/core/src/lib.rs) · [Panda dispatcher](../crates/coding/src/lib.rs) |
| **10. Package distribution** | Panda can load skills already on disk. It has no resource-package manager. | Discover and filter package resources, support local/git/npm sources as appropriate to the compatibility decision, and add install/list/update/remove, project/user scope and selective activation. Check an end-to-end package containing a prompt and a skill before adding executable extensions. [Pi packages][packages] · [Panda discovery](../crates/local/src/skills.rs) |
| **11. Tool registry, validation and scheduling** | Mode selects a fixed schema list. Handlers check fields as needed. The core executes each tool call in order, emits text results, then polls queued input. | Give each tool a schema, result type and execution policy. Validate before dispatch, allow parallel batches and per-tool serialization, and expose configurable all-at-once or one-at-a-time queue delivery. Add direct, deferred and hidden tools and branch-aware discovery via `tool_search`. Check that a deferred tool stays loaded when its branch resumes and that additional entry points obey Panda's mode policy. [Pi agent loop][loop] · [Pi tool exposure][cli] · [Panda turn loop](../crates/core/src/lib.rs) |
| **12. MCP client** | The CLI has no MCP server configuration, transports or resource commands. | Add stdio and Streamable HTTP, connection lifecycle, authentication, tools, resource lists/templates/reads, and per-server or per-tool exposure. Pi ships this as a built-in extension. Start with one explicit stdio tool and one HTTP resource, then add deferred discovery, OAuth, reconnect and interactive management. [Pi MCP][mcp] · [Panda tool catalog](../crates/coding/src/lib.rs) |
| **13. Codemode** | The shell tool runs workspace commands. There is no isolated script runtime that composes registered tools. | Port the optional ability to run model-written JavaScript with injected tools, discovery, stored values, bounded execution and selected output returned to the model. Exercise two nested calls, cancellation and an oversized result. This depends on the registry and its permissions. [Pi Codemode][codemode] · [Panda workspace interface](../crates/coding/src/lib.rs) |
| **14. RPC, JSON events and a session SDK** | Panda has all four interaction modes and an in-memory second host. Its RPC prompt takes `text`, cancellation is `cancel`, and it emits ID-tagged events followed by `done`. | Pi clients send `prompt.message`, receive an acceptance response, observe lifecycle events through `agent_settled`, and use `abort`. Add state/messages/tree queries, model and queue controls, session switching/forking, compaction/retry, bash, and extension UI requests. Expose those operations through a shared Rust session API. If Panda needs Pi wire compatibility, test a versioned adapter with a Pi client fixture and keep existing Panda clients working. [Pi RPC][rpc] · [Command reference][rpccommands] · [Pi SDK][sdk] · [Panda protocol](../crates/cli/src/automation.rs) |

## Providers, terminal and distribution

| Feature | Panda 0.1.12 | Remaining Rust work |
|---|---|---|
| **15. Custom endpoints and native providers** | The CLI selects DeepSeek, OpenRouter or ChatGPT Codex. The Rust chat adapter takes an endpoint, but a user cannot register their own provider in configuration. | First expose a configurable OpenAI-compatible endpoint and model metadata so a user can select a local Ollama, llama.cpp or vLLM model. Then port native Anthropic Messages, direct OpenAI API-key Responses and Google Gemini. Bedrock, Vertex, Azure, Copilot, Radius and Pi's other named providers add their own authentication or routing requirements. Test tool calls and switching providers mid-session for each wire family. [Pi model config][models] · [Pi provider inventory][ai] · [Panda catalog](../crates/providers/src/models.rs) |
| **16. Model identity and authentication lifecycle** | Codex browser/device login and refresh, saved API keys, live lists, reasoning selection and context windows exist. Startup reads a shared model selection. Assistant messages omit the responding provider and model. | Restore model selection per session/branch and record the actual responder per message. Add model scopes and cycling, credential check/logout, capability-aware input conversion and catalog overrides. Later, expose virtual models that can route each request and the optional llama.cpp management UI. After changing the global default, reopen a branch and check that it still identifies the model that produced an earlier answer. [Pi session entries][format] · [Virtual models][virtual] · [Provider authentication][providers] · [Panda session type](../crates/core/src/lib.rs) |
| **17. Usage, caching and transport** | Panda records input/output token counts and cost when the provider supplies it. Retry and context budgets have built-in defaults. | Normalize cache reads/writes and per-model costs, distinguish usage for failed attempts and summaries, support pricing metadata, and expose retry/timeout and supported SSE/WebSocket transport choices. Consider Pi's cost-aware prompt-cache warming after the accounting is reliable. [Pi settings][settings] · [Pi usage accounting][usage] · [Panda usage records](../crates/core/src/lib.rs) |
| **18. Terminal customization and diagnostics** | Fullscreen Markdown, diff excerpts, copy, reasoning/tool toggles, path completion, a Vim editor and external editor support are present. | Add user themes and keybindings with active-hotkey help, a regular scrollback mode, inline terminal image rendering, and extension-owned UI surfaces. Later candidates include a diagnostic dump, changelog viewer, local bug-report bundle, and explicit external sharing of a transcript. [Pi terminal usage][ui] · [Pi terminal library][tui] · [Panda screen](../crates/cli/src/screen.rs) |
| **19. Supported platforms** | The shipped host targets Intel and Apple Silicon macOS and launches workspace tools through Seatbelt. | Linux and Windows CLI parity needs native execution/isolation, process cancellation, clipboard and terminal behavior, installers, and native runner coverage. Keep this as a platform milestone if Panda expands beyond its macOS first-release goal. [Pi installation][pi] · [Pi Windows guide][windows] · [Panda host](../crates/local/src/sandbox.rs) |

## Wider monorepo scope

- **Additional model operations.** Pi's AI library also has separate image-generation and classification APIs, including TypeSafe, and Codemode can call them. Panda's image support is input for chat. These are candidates for a broader Rust AI SDK. [Pi AI library][ai] · [Codemode model operations][codemode]
- **Durable and remote execution.** Pi Durable is an experimental persistent conversation/task/document runtime. Pi Env ships a Rust daemon for workers to execute tools on another machine. Panda already has SQLite sessions, interrupted-call acknowledgement and a swappable workspace trait. Evaluate the daemon's protocol before committing to a port. [Pi Durable][durable] · [Pi Env][env] · [Panda recovery](../crates/core/src/lib.rs)
- **Distributed apps.** Chord supplies versioned objects and hot-reloaded plugins across processes. The monorepo also contains the experimental p2 UI, a native macOS wrapper spike, and the headless p3 successor. Their project sidebar, workers and web/desktop surfaces belong to a separate multi-host product decision. [Chord][chord] · [p2][p2] · [p2-mac][p2mac] · [p3][p3]
- **Supporting libraries.** Pi ships shared telemetry contracts, schema validation and behavioral evals. Adopt their event or validation semantics where an integration needs them. Panda can reuse Rust libraries and adapt upstream fixtures. [Telemetry][telemetry] · [Schema][schema] · [Evals][evals]
- **Subagents and plan mode.** Upstream's coding CLI describes both as extension workflows. Panda already ships plan mode. A subagent feature would be a product choice or an extension port with its own reference implementation. [Pi coding CLI][codingpi] · [Panda plan-mode policy](../crates/coding/src/lib.rs)

## Verification

The comparison used the source and documentation at the two revisions above. Locally, 26 Panda tests passed across `panda-core`, `panda-coding`, `panda-local` and `panda-memory` with `cargo test --locked --offline -p panda-core -p panda-coding -p panda-local -p panda-memory`. They cover existing behavior including plan-mode dispatch, retries, compaction, paginated search and persisted branch navigation. The proposed checks in the tables are acceptance criteria for future ports. This comparison did not exercise live providers, upstream's runtime or hosted CI.
